# Contributing to Vibestack

## Contribution Standard
Every contribution must improve one or more of: architecture quality, portability, modularity, or token efficiency.

## Workflow
1. Open an issue with problem framing and expected outcomes.
2. Identify impacted modules in `.vibestack`.
3. Propose technical approach with tradeoffs.
4. Implement with focused, reviewable commits.
5. Update memory artifacts with decision rationale.

## Pull Request Requirements
- Architecture rationale and alternatives considered.
- Runtime compatibility impact statement.
- Security implications and mitigation plan.
- Documentation updates for changed behavior.
- Verification evidence and residual risk note.
